Exp4 step 06 · Remove command arrival priority

Result

The optional server mode is implemented, built and installed at /usr/local/bin/rcssserver. Models and physics equations are unchanged. The next 200 games can test perception improvements without giving the faster team's player actions first priority.

The previous 60-game audit found that new foul charges blocked 238 of 248 left kicks, versus 32 of 276 right kicks in that selected foul-overlap group. Those counts describe that group, not all kicks. The treatment took longer to decide, and ordinary receive-time execution could penalize its later kick.

What changes

Before New optional mode
Gameplay handlers execute as UDP messages are processed. The server collects each participating player's actions until its done.
A faster response can kick before a later foul or tackle. After every participant finishes, the server shuffles the player batches once and executes them.
Receive polling consumes the shared random generator. Receive polling does not consume physics randomness; command ordering uses its own generator.
A synchronous timeout can continue with missing commands. An incomplete batch is discarded and the match exits with failure, without saving a scored result.

The server preserves each player's command sequence and existing action limits. It randomizes player priority, rather than individual commands. The mode defaults to off and requires synchronous play.

A cycle's order depends on the configured order seed, simulation cycle, stopped-cycle count and participating player identities. It does not depend on receive order or number of polling calls. A new automatically selected seed is recorded for each game when command_order_seed=-1.

Run the next 200 games

Keep the current quantized 360° experiment settings, left-side model flags and stock right-side launch. Add these server arguments in the game runner:

-server::synch_mode=true \
-server::randomize_player_commands=true \
-server::command_order_seed=-1 \

The plain server::name=value form also works when invoking the server directly. Use a new player log directory, for example /home/nader/workspace/denoise/logs/exp3-f5-logs, and a separate game result directory. Keep unique game IDs and the runner's existing game_log_fixed=true and game_log_fixed_name=$GAME_ID. There is no new start.sh option.

The server writes <game_log_dir>/<GAME_ID>.command-order.csv even when ordinary game/text logging is off. Columns record cycle, stopped count, round, resolved seed, execution order and queued handler counts. Counts exclude done and immediate protocol queries. Received-command RCL order is still receive order; use the CSV for actual execution priority.

For reproducible controlled probes, set nonnegative command_order_seed and random_seed. Normal batches can retain automatic seeds. Both seeds and the scheduling flags are mirrored into v19 player metadata.

Implementation notes for future work

  • Gameplay actions, including neck, view, attention and say, queue only during parsing in an open think window. Physics/internal handler calls execute normally. Both generated parsing and the Cygwin fallback reach the same guarded handlers; no grammar change was needed.
  • Queries, initialization, transport options and coach/trainer commands retain immediate semantics. The existing coach/trainer done barrier remains. Trainer interventions are outside the tested player-order invariant.
  • Each queue is bounded at 128 handlers. A malformed command, overflow or missing barrier response invalidates the experiment instead of committing a partial batch. New connections join at the next collection window.
  • Actions after done or outside a collection window are dropped. Legacy UDP messages have no cycle identifier: an arbitrarily delayed duplicate arriving inside a later open window cannot be identified perfectly without a protocol extension.
  • A match that times out must be rerun to count toward 200 completed games. The existing synchronous wait limit is retained.
  • This is an opt-in research scheduling rule. Compare both teams under this same rule; keep standard-server results as a separate condition.
